# SuperfastSAT 블로그 포스팅 스킬

SAT 및 미국 입시 관련 네이버/구글/랜딩 페이지 블로그 포스팅을 작성하는 스킬입니다.
"친절하게 설명하는 전문가" 톤으로, RESOURCE(프로젝트 파일 + 웹 검색 자료)만 근거로 본문을 작성합니다.

---

## 프로젝트 데이터 안내

이 스킬에서 사용하는 프로젝트 데이터 파일은 다음과 같습니다.

| 파일 | 설명 | 용도 |
|------|------|------|
| `master_sat_ontology.jsonl` | SAT 문제 1,177개 (지문·선택지·정답·해설·knowledge_graph 포함) | 문제 유형별 분석, 오답 패턴 추출, 예시 문제 활용 |
| `sat_ontology_atlas.json` | 1,177개 문제의 인덱스 (skill, difficulty, parent_concept, prerequisite) | 빠른 필터링·집계용 |
| `assessment_framework.md` | College Board 공식 Digital SAT Assessment Framework (~19,000줄) | SAT 설계 원리, 섹션 구조, 채점 기준 등 공식 근거 |
| `assessment_atlas.csv` | assessment_framework.md의 챕터별 요약 인덱스 (44행) | 필요한 챕터를 빠르게 찾기 위한 목차 |
| `DATA_SUMMARY_superfastsat.md` | SuperfastSAT 전반 데이터 요약 | 포스팅 기획 및 전체 맥락 파악용 |

**데이터 활용 워크플로:**
1. 토픽 확정 후 `project_knowledge_search`로 관련 내용 검색
2. 데이터 분석이 필요하면 Python/bash로 JSONL·JSON 파일 집계
3. 공식 근거가 필요하면 `assessment_atlas.csv`에서 챕터 찾고 → `assessment_framework.md` 해당 부분 참조
4. 웹 검색은 레퍼런스 URL 수집과 최신 정보 보완용으로 사용

## [네이버 전용] STEP -1: 키워드 분석

**네이버 블로그 플랫폼일 때만 적용합니다.** 토픽 확정 전 검색 경쟁도를 먼저 확인합니다.

### 블루오션 키워드 판단 기준

좋은 키워드 = 검색 수요는 있지만 경쟁 글이 적은 키워드입니다.

| 블로그 검색 결과 수 | 판단 |
|-------------------|------|
| 시드 키워드의 1% 미만 | 블루오션 (선택 추천) |
| 1~10% | 보통 경쟁 |
| 10% 초과 | 레드오션 (피하거나 더 구체화) |

**확인 방법**: 네이버에서 `site:blog.naver.com "키워드"` 검색 후 결과 수 비교

### 롱테일 키워드 선호 규칙

단어 수가 많을수록 경쟁도가 낮고 전환율이 높습니다.

```
❌ 짧은 키워드: "SAT 수학"  → 경쟁 과다
✅ 롱테일 키워드: "SAT 수학 모듈2 시간 부족 해결법"  → 블루오션 가능성 높음
```

- 3단어 이상 구체적 키워드를 우선 선택합니다
- 점수대 + 상황 + 해결책 조합이 효과적입니다 (예: "SAT 1200점 Reading 틀리는 이유")
- `naver-blog-auto`가 설치된 경우: `streamlit run naver-blog-auto/app/main.py` → 키워드 탭 활용

### 확정 기준

- 검색 결과 수가 경쟁 키워드의 10% 이하
- 타깃 독자의 실제 검색 의도에 부합
- 기존 포스팅과 중복되지 않음

## STEP 0: 정보 수집

아래 항목이 대화에서 아직 확인되지 않은 경우에만 질문합니다. 이미 확인된 항목은 다시 묻지 않습니다.

1. **플랫폼**: 네이버 블로그 / 고스트(구글) / 랜딩 페이지(superfastsat.com)
2. **주제 영역**: Reading & Writing / Math / 종합 전략 / 입시 전략 / 데이터 분석
3. **타깃 독자**: 점수대 + 목표 (예: 1200~1350점대 → 상위권 목표)
4. **리소스**: 프로젝트 파일 / 웹 서칭 / 둘 다
5. **구체적 토픽**: 없으면 주제 영역 기반으로 3개 제안 후 확정
6. **TARGET BELIEF**: 독자가 이 포스팅을 읽은 후 가져야 할 핵심 믿음 1문장
7. **COMPETING BELIEF**: 독자가 지금 갖고 있을 가능성 높은 반대 믿음 1문장
8. **BELIEF BRIDGE**: 경쟁 믿음 → 목표 믿음으로 이동시키는 핵심 논증 1개 (RESOURCE 기반)

> **BELIEF BRIDGE 사전 검증 (3문항 모두 통과해야 STEP 1로 진행)**
>
> Q1. COMPETING BELIEF를 가진 독자는 내 BRIDGE에서 어느 지점에서 막히는가?
> Q2. 그 막히는 지점을 해소할 근거가 아래 중 하나 이상의 형태로 RESOURCE에 존재하는가?
>   - **(b) 데이터**: 수치, 비율, College Board 통계, 실제 문제 분석 결과
>   - **(c) 메커니즘**: "왜 이 방법이 작동하는가"를 설명하는 인과 사슬
>   - *(a) 사례(anecdote)만으로는 부족합니다 — 설득은 (b) 또는 (c)에서 일어납니다*
> Q3. (b)(c) 근거가 없으면 → 웹 검색으로 확보하거나, 주장 자체를 수정합니다.
>
> 이 3문항을 통과하지 못한 주장은 글이 완성되어도 독자를 설득하지 못합니다.

데이터 분석 포스팅의 경우: JSON·CSV 데이터 파일이 있으면 코드(Python/bash)로 실제 집계 후 수치를 본문에 반영합니다. 가상 수치는 절대 사용하지 않습니다.

## STEP 1: 리소스 확보

### 1-0. 스타일 샘플 참조 (있을 경우만)

`blog_database/style_samples.jsonl`이 존재하면, 작성 전에 최근 5개 항목을 읽습니다.

```python
import json
samples = []
try:
    with open('blog_database/style_samples.jsonl', 'r', encoding='utf-8') as f:
        for line in f:
            if line.strip():
                samples.append(json.loads(line))
except FileNotFoundError:
    pass
recent = samples[-5:]  # 최근 5개
```

각 샘플에서 `original`(AI 초안)과 `edited`(사용자 수정본)를 비교해
반복적으로 수정되는 패턴을 파악하고 이번 포스팅에 미리 반영합니다.

**이번 포스팅에 즉시 적용하는 방법 (인컨텍스트 학습)**

샘플을 읽은 후, 다음 질문에 답하며 현재 포스팅 초안에 반영합니다.

1. 사용자가 반복적으로 **삭제**한 표현이 있는가? → 이번 초안에서 그 표현 사용 금지
2. 사용자가 반복적으로 **추가**한 문장 유형이 있는가? → 유사한 위치에 미리 삽입
3. 사용자가 문장을 **짧게 자르는** 패턴이 있는가? → 이번 초안부터 문장을 더 짧게
4. 사용자가 **줄바꿈을 추가**하는 경향이 있는가? → 강조 문장에 단독 줄 부여

**장기 규칙 업데이트 방법 (SKILL.md 자동 반영)**

샘플이 일정량 쌓이면 `/analyze-blog-style` 명령을 실행합니다.
반복 패턴이 배코치 문체 DNA 규칙으로 추출되어 이 SKILL.md에 직접 추가됩니다.

샘플이 없으면 이 단계를 건너뜁니다.

### 1-1. 프로젝트 파일 분석
- `project_knowledge_search`로 토픽 관련 내용을 먼저 검색합니다.
- 데이터 분석이 필요하면 Python/bash 코드로 집계해 실제 수치를 추출합니다.
- `assessment_framework.md`에서 공식 근거를 확인합니다.

### 1-2. 웹 검색
- 확정된 토픽의 핵심 개념·규칙 5~8개를 키워드로 웹 검색합니다.
- College Board 공식 문서를 1순위로 수집합니다.
- 수집한 자료는 레퍼런스용으로만 사용하고, 본문에 새로운 사실을 추가하지 않습니다.

## STEP 2: 포스팅 작성

### P0 절대 규칙 (모든 포스팅에 강제 적용)

**문체**
- 전체 문장은 반드시 **"합니다/입니다"** 체로 작성합니다.
- "~다/~이다" 체는 금지입니다. (인용·용어 예시의 아주 짧은 문장만 예외)

---

### 배코치 문체 DNA (실제 완성본 기준 — 반드시 준수)

실제 완성된 포스팅에서 추출한 문체 규칙입니다. P0 문체 규칙과 동일한 강제력으로 적용합니다.

**① 문단 리듬 — 짧게 끊기**
- 한 문단 = 2~4줄. 줄바꿈을 강조 수단으로 적극 활용합니다.
- 긴 설명은 한 문장씩 줄을 나눠 씁니다.

잘못된 예:
> Hard Module 2에 배정된 수험생들 사이에서 가장 많이 언급된 것은 시간 압박이었습니다. 연습 시험에서 800점에 가까운 점수를 받던 수험생들도 "Module 2에서 시간이 부족해서 마지막 몇 문제를 대충 찍었다"는 반응이 적지 않았습니다.

올바른 예:
> 일단 Hard Module 2에 배정된 학생들 사이에서
> 가장 많이 언급된 것은 시간 압박이었습니다.
>
> 연습 시험에서 800점에 가까운 점수를 받던 학생들도
> "Module 2에서 시간이 부족해서
> 마지막 몇 문제를 대충 찍었다"는 반응이 적지 않습니다.

**② 반전 구조 — 예상 깨기**
- 독자의 예상 반응(다짐·안도·결심)을 먼저 써주고,
  바로 다음 줄에서 현실을 짚어주는 반전을 섹션당 1회 허용합니다.
- 예:
  > "다음 시험 전에 이 부분은 확실히 보완해야겠다"는 다짐
  >
  > 그리고는 어떻게 하느냐.
  > "다짐"을 잊습니다.
  >
  > 이러면 결국은 목표 점수는 영원히 로또의 영역에 남습니다.

**③ 마무리 — 선언형으로 끊기**
- "요약 2문장 + 오늘 할 일 1문장" 기존 규칙 유지하되,
  마지막 문장은 반드시 **"이것 기억하세요"** 또는 **"일단 이렇게 기억하세요"** 로 끝냅니다.
- 설명을 덧붙이지 않습니다. 줄바꿈으로 강조를 대신합니다.
- 예:
  > 일단 이렇게 기억하세요
  > 5월, 8월 시험을 준비하신다면
  > Hard Module 2를 기준으로
  > RW는 어휘·추론·연결어 패턴을
  > Math는 Desmos 없이 문제 푸는 연습
  > 해야 한다는 것, 이것 기억하세요.

**④ 독자 호칭**
- "수험생" → **"학생"** 으로 기본 사용합니다.
- 학부모가 독자에 포함될 때는 **"학생, 학부모님"** 을 병기합니다.
- 도입부 타깃 불릿에도 "학생" 호칭을 사용합니다.

**⑤ "바쁘시면 이것만 보세요!" 형식**
- 항목별로 줄바꿈해서 한 항목 = 한 줄로 씁니다. 붙여 쓰지 않습니다.
- 예:
  > 3월 SAT는 Module 2가 체감상 크게 어려웠고,
  > RW는 어휘와 추론,
  > Math는 Desmos 의존을 벗어난 문제에 대해
  > Reddit에서 이야기가 활발합니다.

**⑥ 감탄 표현 허용**
- 난이도 급등·충격 묘사 시 따옴표 안 단음절 감탄어 1회 허용합니다.
- 예: `Module 2는 "헉"입니다.`

**⑦ Reddit 인용 후기 형식**
- 수험생 반응은 큰따옴표 안에 구어체로 짧게 씁니다.
- 예: `"마지막 3문제는 뭘 입력해야 할지도 몰랐다"`

**⑧ 설득 공식 — 통념 해체형 (1인칭 고백형 금지)**

배코치는 독자에게 '함께 배우는 사람'이 아니라 '이미 아는 사람'으로 포지셔닝합니다.

❌ 금지: `"저도 처음엔 X라고 생각했습니다"` → 배코치 전문성 훼손
❌ 금지: `"저도 그 함정에 빠진 적 있습니다"` → 권위 훼손형 공감

✅ 사용: **[통념 인정] + [데이터/반전] + [독자 판단 유도]**

형식:
```
[통념 인정] "보통 X라고들 생각합니다."
[데이터/반전] "그런데 실제 데이터를 보면 Y입니다."
[독자 판단 유도] "직접 확인해 보시면 이해가 될 겁니다."
```

STEP 0에서 설정한 COMPETING BELIEF를 [통념 인정]에, BELIEF BRIDGE를 [데이터/반전]에 대응시킵니다.

**도입 3파트 (순서·문구 고정)**

글의 시작은 반드시 아래 3파트 순서로 작성합니다.

```
[1] 이런 분들에게 도움을 드리고자 썼습니다.
    - '-' 불릿 2~4개
    - 타깃 독자(점수대·상황)를 그대로 반영
    - 조건은 RESOURCE 또는 POST BRIEF에 있는 것만 사용

[2] 목차 (BELIEF BRIDGE 논증 단계 수 = 섹션 수)
    - STEP 0의 BELIEF BRIDGE에서 논증이 N단계이면 목차 N개
    - 플랫폼 제약: 네이버 2~5개 / 고스트·랜딩 제한 없음
    - 각 목차 항목 = 그 논증 단계의 핵심 주장 (선언형 또는 의문형)
    - 본문 헤딩은 목차 문구를 1:1로 그대로 복사 (띄어쓰기 포함)

[3] 바쁘시면 이것만 보세요!
    - 항목별 줄바꿈으로 씁니다 (배코치 문체 DNA ⑤ 참조)
```

내러티브 오프닝(사례 오프닝)은 사용하지 않습니다.

**목차-본문 일치**
- 목차 항목 수 = STEP 0 BELIEF BRIDGE 논증 단계 수 (플랫폼 제약 내)
- 도입 [2] 목차 문구 = 본문 섹션 헤딩 문구 **1:1 완전 일치** (띄어쓰기 포함)
- 목차에 없는 추가 헤딩·섹션 금지

**CTA 완전 금지**
- 금지: 상담·문의·DM·카톡·링크·신청·수업·구매·구독·팔로우 유도
- 허용: '학습 행동'만 (예: "오늘 표시하고 다시 풀어보시면 됩니다.")
- 마무리 문단: 배코치 문체 DNA ③ 선언형 마무리로 끝냅니다.

**사실성: 본문은 RESOURCE-only**
- RESOURCE에 없는 사실·수치·단정은 본문에 쓰지 않습니다.
- 예시가 필요하지만 RESOURCE에 구체 예시가 없으면 **"가상 예시"** 로 제시합니다.
  - 반드시 '이런 상황을 상상해 보자구요'라고 명시합니다.
  - 가상 예시에 RESOURCE에 없는 수치·통계·기관명은 사용하지 않습니다.
- 데이터 분석 포스팅: 코드로 추출한 실제 수치만 사용하고, 수치 옆에 분석 근거를 한 문장으로 명시합니다.

### 본문 작성 규칙

- 본문 헤딩 수 = 목차 수 (STEP 0에서 결정된 논증 단계 수). 추가 헤딩 금지.
- 각 섹션은 최소 2개의 핵심 아이디어를 포함합니다.
- 설명은 자연어 문단으로 씁니다. 단, 배코치 문체 DNA ① 리듬 규칙을 따릅니다.

**근거 유형 기준 (핵심 주장 1개당 적용)**

모든 핵심 주장에는 아래 3종류 중 최소 1개가 있어야 합니다:

| 유형 | 설명 | 설득 강도 |
|------|------|---------|
| **(a) 사례** | "이런 문제에서 이렇게 적용했다" | 약함 — 단독 사용 금지 |
| **(b) 데이터** | 수치·비율·College Board 통계·문제 분석 결과 | 강함 |
| **(c) 메커니즘** | "왜 이 방법이 작동하는가"의 인과 사슬 | 가장 강함 |

- (a)만 있는 주장 = 일화(anecdote). 독자를 설득하지 못합니다.
- STEP 0 BELIEF BRIDGE의 핵심 논증에는 반드시 **(b) 또는 (c)**가 있어야 합니다.
- (b)(c)가 RESOURCE에 없으면 → 웹 검색으로 확보하거나 주장을 수정합니다.

**개념 깊이 기준**

전문 개념(교육학·심리학·시험 설계 용어 등)을 본문에 도입할 때,
반드시 아래 3단계를 거칩니다.

① 한 줄 정의
② SAT 학습 맥락의 구체적 장면 (학생이 "아 그 상황" 하고 떠올릴 수 있는 수준)
③ 이 개념이 독자의 판단·행동에 어떻게 연결되는지

3단계 중 ②가 빠지면 용어만 던진 것이고, ③이 빠지면 교과서 발췌입니다.

**분류형 가이드 복잡성 기준**

점수대·유형·방식 등으로 독자를 분류할 때,
단일 축(점수만, 방식만)으로 1:1 매칭하지 않습니다.
최소 2축(예: 점수 × 자기조절 수준, 점수 × 약점 영역)을 교차해서
같은 범주 안에서도 분기가 보이도록 합니다.
독자가 "나는 이 경우"를 스스로 찾아갈 수 있어야 합니다.

**내부 설계용 체크리스트 (원고에 라벨로 출력 금지)**
작성 시 아래를 내부적으로 확인하되, 원고에는 자연어 문단으로만 풀어 씁니다.
- 개념을 한 문장으로 잡기
- OK/NG 경계선 제시
- 왜 헷갈리는지 (독자 오류 습관)
- 스스로 확인하는 질문 1개
- 오답 신호 (RESOURCE에 있는 것만)
- 예시 (리소스 예시 또는 가상 예시)

### 예시 조건부 삽입 규칙

예시는 '필수'가 아니라 '조건부'입니다.

**트리거 (해당하면 예시 1개 삽입)**
- A) 추상도가 높아 그림이 안 그려질 때
- B) OK/NG 경계가 미세할 때 (May vs Will, 동시 존재 vs 인과 등)
- C) 타깃 증상과 직결될 때 (상식 개입, 소거 애매함 등)
- D) "점프(범위 확대·인과 단정·확신도 상승·가치 판단 추가)"를 설명할 때
- E) 규칙 나열로 건조해질 위험이 있을 때

**예시 억제**
- 바로 앞에서 같은 유형 예시를 이미 썼으면 생략합니다.
- 가상 예시가 사실처럼 보일 위험이 있으면 생략합니다.
- 섹션이 과밀하면 예시를 생략하고 문장을 더 쉽게 풉니다.
- 같은 섹션에서 예시 연속 2개 이상 금지입니다.

### 표 조건부 삽입 규칙

표는 '필수'가 아니라 '조건부'입니다. 문단으로 충분한 내용은 문단으로 씁니다.

**트리거 (아래 중 하나에 해당하면 표 사용)**
- A) 두 가지 이상의 대상을 특성별로 비교할 때 (예: SAT vs ACT, Module 1 vs Module 2)
- B) 데이터 분석 결과를 수치로 정리할 때 (예: 유형별 출제 비율, 난이도별 문항 수)
- C) 시험 일정·날짜·마감일 등 시간순 정보를 나열할 때
- D) 단계별 프로세스를 순서와 내용으로 정리할 때 (예: 채점 과정, 학습 루틴)

**표 작성 규칙**
- 열 수는 2~4개로 제한합니다 (모바일 가독성 우선).
- 셀 안 텍스트는 1~2줄 이내로 짧게 씁니다.
- 표 직전에 표의 맥락을 안내하는 문장 1개를 반드시 씁니다 (표만 덩그러니 놓지 않습니다).
- 표 직후에 핵심 시사점을 1~2문장으로 짚어줍니다.
- 한 포스팅 내 표는 최대 3개까지 허용합니다 (과용 방지).

**표 억제**
- 항목이 2개 이하이면 문장으로 풀어 씁니다.
- 바로 앞 섹션에서 이미 표를 사용했으면 연속 사용을 피합니다.

SuperfastSAT 공식 랜딩 페이지(superfastsat.com)에 올리는 블로그 포스팅은
아래 규칙을 적용합니다. 구글 검색 노출이 목적이며, E-E-A-T와 브랜드 철학이 동시에 반영됩니다.

**핵심 문체 원칙: "네이버보다 더 친절하고 구조적으로 설명하되, 톤은 현실 직시형으로"**

SuperfastSAT 브랜드 철학(행동 우선 / 환경 > 의지 / 사고 방식 전달)을
문체에 직접 반영합니다.

> 네이버의 "코치 구어체"도, 고스트의 "전문가 산문"도 아닌
> **학생의 현실을 직시시키되, 개념은 네이버보다 더 친절하게 풀어주는 톤**입니다.

**⚠️ 깊이 우선 원칙 (랜딩 페이지 최상위 규칙)**

랜딩 페이지 문체 규칙(진단형 도입, 현실 직시, 간결한 톤)과
개념 깊이 기준(정의 → 장면 → 행동 연결 3단계)이 충돌할 때,
**개념 깊이가 항상 우선합니다.**

- "간결하게"는 문장을 짧게 쓰라는 뜻이지, 설명을 생략하라는 뜻이 아닙니다.
- 랜딩 페이지는 구글 검색 + AI 검색 노출이 목적이므로,
  개념을 충분히 풀어야 Helpful Content 판정과 AI 인용 소스 선택에 유리합니다.
- 전문 개념 도입 시 3단계를 네이버보다 **더 풍부하게** 쓰되, 톤만 현실 직시형으로 바꿉니다.
- 출처·학자명을 명시하면 E-E-A-T Expertise가 강화됩니다.

### 랜딩 페이지 문체 4가지 규칙

**① 진단형 도입 — 학생의 현실을 먼저 꺼낸다**

네이버의 "이런 분들에게" 타깃 나열 대신,
학생이 지금 겪고 있는 상황을 직접 짚는 문장으로 시작합니다.

금지:
> "SAT 시험 일정이 궁금한 학생과 학부모님에게 도움을 드리고자 썼습니다."

허용:
> "3월 시험이 끝났습니다.
> D-43이라는 숫자를 보고 '아직 괜찮다'고 생각했다면,
> 이 글을 끝까지 읽어야 합니다."

**② 현실 직시 구조 — 믿음이 아니라 데이터로 말한다**

학생의 막연한 기대를 수치로 직시시킵니다.
"환경이 의지보다 강하다" 철학을 반영합니다.

**주의: 현실 직시 = 내용 압축이 아닙니다.**
수치로 현실을 보여준 뒤에, 그 수치가 왜 그런지를 충분히 설명합니다.
개념이 등장하면 3단계(정의 → 장면 → 행동 연결)를 네이버보다 더 친절하게 풀어줍니다.

금지:
> "충분한 시간이 있으니 지금부터 열심히 준비하세요."

허용:
> "달력에는 43일이 남아 있습니다.
> 실제로 SAT 공부에 쓸 수 있는 날은 25일입니다."

**③ 사고 과정 유도 — 결론을 주지 않고 질문을 던진다**

"설명보다 사고 방식이 중요하다" 철학을 반영합니다.
정답을 제시하는 대신, 독자가 스스로 판단하도록 유도합니다.

금지:
> "5월 시험을 목표로 하면 됩니다."

허용:
> "5월과 6월 중 어느 시험이 맞는지는
> 지금 점수가 어디 있느냐에 달려 있습니다."

**④ 행동 촉구 마무리 — "결국 해내는 학생"을 향한 1줄**

화려한 CTA 없이, 현실의 무게로 행동을 만듭니다.

금지:
> "지금 바로 시작하세요! 상담 신청하기 →"

허용:
> "해야 할 공부는 없어지지 않습니다.
> 미루는 만큼 이자가 붙습니다."

### 네이버 → 랜딩 페이지 변환 시 내용 유지 규칙

네이버 포스팅을 랜딩 페이지 톤으로 변환할 때,
**톤만 바꾸고 내용의 깊이는 오히려 늘립니다.**

랜딩 페이지는 구글 SEO + AI 검색 대응이 목적이므로,
네이버보다 개념 설명이 더 구조적이고 친절해야 합니다.
"간결하게 바꾼다"가 아니라 "톤을 바꾸면서 깊이를 유지하거나 늘린다"가 원칙입니다.

변환 시 깎이기 쉬운 3가지를 반드시 점검합니다.

① **개념 설명**: 네이버 원본에서 3단계(정의 → 장면 → 행동 연결)로 풀었던 개념을
   랜딩 페이지에서는 **동일하거나 더 풍부하게** 풀어 씁니다.
   출처·학자명 명시, 표를 활용한 OK/NG 비교 등으로 E-E-A-T를 강화합니다.
   톤이 바뀌는 것이지 내용이 줄어드는 것이 아닙니다.

② **분류 분기**: 네이버 원본에서 2축 이상으로 교차 분류했던 가이드를
   "간결하게"라는 이유로 단일 축 1:1 매칭으로 되돌리지 않습니다.

③ **구체적 장면·사례**: 네이버 원본에 있던 학습 장면 묘사를
   삭제하지 않습니다. 랜딩 페이지 톤에 맞게 표현만 바꿉니다.

### 변환 예시: 개념 설명이 얕아지는 실패 패턴

아래는 '스캐폴딩' 개념을 다룬 동일 내용의 네이버 vs 랜딩 페이지 버전입니다.

**❌ 실패하는 랜딩 페이지 변환 (내용이 얕아진 경우)**

> SAT를 잘 본 것과 SAT를 잘 가르치는 것은 다릅니다.
> 학생이 막히는 지점에서 "여기서 왜 버벅거리는 거지?"라는 반응이 나오는 선생님은
> 스캐폴딩—실시간 맞춤 지원—을 제공하지 못하고 있는 것입니다.

이 버전의 문제:
- ② 학습 장면이 통째로 빠졌습니다 (ZPD, 힌트 조절, 수업 경험 없음).
- "스캐폴딩—실시간 맞춤 지원—"이라는 괄호 정의 하나로 압축 → 용어만 던진 것입니다.
- 출처(비고츠키)가 빠져서 E-E-A-T Expertise도 약해졌습니다.

**✅ 올바른 랜딩 페이지 변환 (톤은 바꾸되 깊이는 유지·강화)**

> 과외를 할 때 가장 많이 하는 일은
> 학생이 "어디서 막혔는지"를 실시간으로 읽는 것입니다.
> 교육학에서는 이것을 '스캐폴딩'이라고 합니다.
>
> '스캐폴딩'에 대해서 간단하게 살펴보고 가겠습니다.
> 스캐폴딩이란 학생의 근접발달영역(비고츠키, 1961),
> 혼자서는 못 풀지만 도움을 받으면 풀 수 있는 그 지점에 맞춰
> 힌트의 양을 조절하는 것을 말합니다.
>
> (표: 스캐폴딩이 잘 된 예 / 안 된 예)
>
> 저희가 SAT 과외를 진행하면서
> 코치님들과 가장 중요하게 여기는 것은
> 이 스캐폴딩을 잘 하는 것입니다.
>
> 그렇다 보니 학습코치로 지원하는 분들과 면접을 볼 때
> 이 분들이 좋은 학교를 진학했고 다니고 있는 것과,
> 예전에 SAT를 잘 본 것은
> SAT를 잘 가르치는 것과는 매우 다른 영역이라는 것을 매번 느낍니다.

이 버전이 올바른 이유:
- ① 정의: "교육학에서는 이것을 '스캐폴딩'이라고 합니다" + 출처(비고츠키, 1961)
- ② 장면: ZPD 설명 + 표로 OK/NG 비교 + "코치님들과 가장 중요하게 여기는 것"
- ③ 행동 연결: "좋은 학교를 진학한 것과 잘 가르치는 것은 다른 영역" → 독자의 선택 기준 제공
- E-E-A-T: 출처 명시(Expertise) + 실제 수업 경험(Experience) + 표(구조화 → AI 인용 유리)

**변환 체크 질문**: 네이버 원본에 있던 ②(학습 장면)가 랜딩 페이지 버전에도 있는가?
없으면 톤 변환이 아니라 내용 삭제입니다. 다시 씁니다.
