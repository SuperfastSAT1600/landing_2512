## STEP 0: 포스팅 유형 선택

"이 포스팅을 읽은 독자는 [동사]할 것이다"를 완성한다.
- 인식이 바뀐다 → **현상형** 또는 **개념형**
- 행동이 바뀐다 → **전략형**, **비교형**, **오류수정형**

| 유형 | 핵심 흐름 | 끝맺음 |
|------|----------|--------|
| **현상형** | 혼란 장면 → 패턴 데이터 → 메커니즘 → 구체 예시 | 구체 예시 (전략 없음) |
| **전략형** | 문제 정의 → 기존 전략 실패 이유 → 새 전략 → 실전 적용 | 구체 행동 |
| **개념형** | 혼동 장면 → 정의 비교 → 판단 기준 → 적용 예시 | 판단 기준 1줄 |
| **비교형** | 선택 상황 → 비교 데이터 → 선택 기준 → 독자 적용 | 독자 자기 판단 |
| **오류수정형** | 오류 장면 → 왜 틀리는지 → 올바른 이해 → 연습 방법 | 확인 행동 |

하나의 주제가 인식·행동 델타를 동시에 유발하면 두 편으로 분리한다.
모든 유형의 끝맺음: **`## 이것 기억하세요`** — H2 섹션 제목으로 쓴다. 독립 문장으로 반복하면 어색하다.

## STEP 0.5: Skeleton Gate (산문 생성 전 필수)

레이블이 아닌 독자의 인식이 이동하는 흐름으로 골격을 잡는다.
H2 섹션을 먼저 정하지 않는다. 흐름이 자연스러우면 헤딩이 없어도 된다.

```
[단일 주장]: 독자의 생각을 A에서 B로 옮기는 방향 — 한 문장
[독자 현재 위치]: 독자가 지금 갖고 있는 구체적 오해 또는 믿음 — 한 문장
[발견의 이유]: "나는 언제, 무엇을 보고 이것을 알았는가" — 한 문장

[인식 흐름]:
  1. 독자가 이 시점에 갖는 질문/혼란: ___
     → 이를 해소하는 데이터 또는 사실: ___
  2. 독자가 이 시점에 갖는 질문/혼란: ___
     → 이를 해소하는 데이터 또는 사실: ___
  N. ...
  (메커니즘이 등장하는 흐름 번호 표시: "메커니즘 — 흐름 N")

[끝맺음]: 독자가 글을 닫을 때 머릿속에 남아야 하는 것 — 한 문장

[주장 추적표]:
  주장: ___ → 근거: ___ (출처 명시)
  주장: ___ → 근거: ___

[단일 주장 점검]:
  이 주장은 출처가 지지하는가, 아니면 내가 만든 연결인가?
  "사실을 전하는 것"만으로 충분한가? — 충분하다면 연결을 추가하지 않는다.
```

**흐름 작성 요령**:
- "독자가 이 시점에 갖는 질문"은 실제 머릿속 질문이어야 한다
- 흐름 1이 흐름 2를 자연스럽게 불러와야 한다
- 메커니즘("왜")이 빠진 흐름은 설명 나열이 된다 — 반드시 한 곳에 포함

### FM 자가진단 (3개, 모두 Pass여야 산문 진행)

| FM | 판정 질문 | Pass 조건 |
|----|----------|----------|
| **FM-A 흐름** | 인식이 흐름 1 → 2 → N으로 전진하는가? 제자리인 흐름 없음? | 모두 전진 |
| **FM-B 설득** | 발견의 이유가 분명한가? 독자 위치가 구체적인가? 단일 주장이 관통하는가? | 모두 YES |
| **FM-C 정합** | 주장 추적표의 모든 수치가 실제 데이터와 일치하는가? | 모순 없음 |

**ANY FAIL → 흐름 수정 후 재진단. 산문 생성 없음.**

## STEP 1: 본문 작성

### 포스팅 구조 (SEO/GEO 고정 요소)

모든 포스팅은 아래 구조를 따른다.

```
[도입부 요약]  — 2~3문장, 산문으로 작성. 이 글이 무엇을 다루고 어떤 결론에 도달하는지.
[본문]         — 인식 흐름을 따라
[함께 읽기]   — 관련 포스팅 2~3개 링크 (## 함께 읽기)
[레퍼런스]    — 본문 인용 출처 (## 레퍼런스)
```

**도입부 요약 작성 규칙**:
- 스타일 박스(TL;DR, 요약 블록)가 아닌 자연스러운 산문 단락
- 글의 핵심 발견 또는 주장을 한 문장으로, 이 글을 읽어야 할 이유를 한 문장으로
- 이 두 문장이 오프닝 장면 바로 뒤에 이어져서 독자를 본문으로 끌어들인다
- AI가 이 단락만 읽고도 글의 핵심을 인용할 수 있을 만큼 명확해야 한다

**함께 읽기 작성 규칙**:
- 이 글의 독자가 자연스럽게 다음으로 궁금해할 주제의 포스팅
- 실제로 존재하는 포스팅만 링크한다. 아직 없으면 생략한다.

---

### 글 본문에 넣지 않는 것

```
✗ "바쁘시면 이것만 보세요!" 박스, 요약 박스, 핵심 정리 박스
✗ ## FAQ / ## 자주 묻는 질문 섹션
✗ ## 목차 / 1. 2. 3. 형태의 번호 목차
✗ "여기서 반전", "핵심은 이것" 구조 신호 레이블
✗ 표 — 데이터를 실제로 비교할 때만 허용
```

이것들은 글 뒤 `_meta` 블록에서 처리한다.

### 문체 규칙

- **합니다/입니다 체** 전체. ~다/~이다 금지.
- 한 문단 2~4줄. 강조 문장은 단독 줄 + 앞뒤 빈 줄. 3문장 이상 이어지는 단락 금지.
- 1인칭 고백형 금지: "저도 처음엔 그랬습니다"
- 독자 호칭: "학생" (학부모 포함 시 "학생, 학부모님")
- 오프닝 패턴: 작성 전 최근 발행 포스팅의 첫 문장을 확인한다. 같은 장면 구조(상담 장면 등)가 이미 쓰였다면 독자 상황을 직접 서술하는 방식으로 대체한다.

### 근거 규칙

핵심 주장에는 데이터(수치·비율) 또는 메커니즘(인과 설명) 중 하나가 있어야 한다.
사례 단독으로는 주장이 되지 않는다. 주장 추적표에 없는 사실은 쓰지 않는다.

### CTA

- 네이버: 완전 금지
- 고스트: 완전 금지 (이부작 1편이면 랜딩 연결 1회 허용)
- 랜딩 페이지: 독자가 글을 읽고 나서 자연스럽게 다음 행동으로 이어지는 포스팅에서만 마지막 문단 1회 허용.
  전략형·비교형·오류수정형 — 허용.
  뉴스 단순 보도형(현상형) — 생략.

## STEP 2: 메타데이터 역산 (본문 완성 후)

본문을 다 쓴 후, 아래를 본문에서 **추출**하여 `_meta` 블록으로 분리한다.
글 본문에 삽입하지 않는다.

```yaml
_meta:
  title_tag: ""         # 60자 이내, 핵심 키워드 앞 배치
  meta_description: ""  # 155자 이내, 수치 포함 — TL;DR 역할을 여기서 한다
  og_title: ""
  og_description: ""
  slug: ""              # 소문자, 날짜 없음, 키워드 포함
  focus_keyword: ""
  category: ""
  tags: []
  # ⚠️ 고스트 전용 태그 규칙: 아래 4개 중에서만 선택. 그 외 키워드 사용 금지.
  #   - SAT Math 자료
  #   - SAT RW 자료
  #   - 미국 입시 뉴스
  #   - 커리큘럼 소개
  author: "SuperfastSAT"
  date: "YYYY-MM-DD"
  target_reader: ""     # 이 글이 가장 도움이 되는 사람 — 본문에서 역산

  # 네이버 전용
  hashtags: []          # 본문에 실제 등장한 키워드 5~10개

  # 랜딩/고스트 전용
  schema_json_ld: |
    {
      "@context": "https://schema.org",
      "@type": "BlogPosting",
      "headline": "",
      "author": {"@type": "Organization", "name": "SuperfastSAT"},
      "datePublished": "",
      "dateModified": ""
    }

  # Supabase posts 테이블 매핑
  supabase:
    title: ""
    excerpt: ""         # 2~3문장 요약
    description: ""     # meta_description과 동일
    content: "[본문 전체]"
```

### 레퍼런스

본문 끝 `## 레퍼런스` 섹션에 노출. 본문에서 인용한 출처만. 최소 3개. URL 포함.
`College Board Question Bank — [범위], SuperfastSAT 분석 (연도)` 형식 사용.

### 네이버 전용: 오프닝 요소

네이버 포스팅만 도입부 요약 앞에 아래 1요소를 배치한다.

```
이런 분들에게 도움을 드리고자 썼습니다.
- 독자 유형 3~5개 (본문에서 역산)
```

## STEP 3: 읽힘 루브릭 (10점 만점)

**8점 미만은 발행하지 않는다.**

```
① 발견의 진정성 (2점)
   2 = 글쓴이가 언제, 무엇을 보고 놀랐는지가 오프닝에서 구체적으로 느껴짐
   1 = 발견이 있지만 "중요합니다", "주목할 만합니다" 수준으로 추상적
   0 = 발견 없음. 정보 나열로 시작.

② 인과의 깊이 (2점)
   2 = "왜 그런가"의 메커니즘이 글에서 명확히 설명됨
   1 = 인과가 있지만 피상적
   0 = 사실만 나열. "왜"가 없음.

③ 독자 위치 정확성 (2점)
   2 = 독자가 "맞아, 나 그렇게 생각했어"를 느낄 수 있는 구체적 오해를 짚음
   1 = "많은 학생이 어려워합니다" 수준으로 추상적
   0 = 독자 위치 파악 없음

④ 흐름의 자연성 (2점)
   2 = TL;DR 박스, FAQ 레이블, 목차, 구조 신호 레이블이 본문에 없음. 산문이 자연스럽게 이어짐.
   1 = 형식 요소가 일부 있지만 읽힘에 크게 방해 안 됨
   0 = TL;DR, ## FAQ, 목차 등이 본문에 삽입됨

⑤ 단일 주장 일관성 (2점)
   2 = 첫 문장과 마지막 문장이 같은 주장을 향하고 있음. 중간에 흔들림 없음.
   1 = 주장이 있지만 중간에 보조 주장이 끼어들어 분산됨
   0 = 주장이 둘 이상이거나 불분명
```

**판정**:
- **8~10점**: 발행
- **6~7점**: 취약 항목 수정 후 재체크
- **5점 이하**: STEP 0.5로 돌아가 인식 흐름 재작성

## STEP 4: 썸네일 생성 (랜딩 페이지 포스팅 전용)

루브릭 8점 이상 통과 후, 발행 전에 썸네일을 만든다.

### 스타일 원칙

- 흰색 배경 (`#ffffff`)
- 검은색 라인 드로잉 (`stroke="#000000"`, `fill="none"`)
- 텍스트 없음 — 그림만
- 크기: `1200 × 630` (16:9)
- 선 굵기: `stroke-width="3"` ~ `"5"` (일관성 유지)

### 주제별 그림 가이드

| 포스팅 주제 | 추천 그림 |
|------------|----------|
| 대학 정책 변화 (의무화, 요건 추가) | 공문서 + 도장, 또는 체크리스트 |
| SAT/ACT 점수 전략 | 점수표, 상승 그래프, 시험지 |
| 슈퍼스코어, 멀티 응시 | 여러 시험지 → 하나로 합쳐지는 화살표 |
| 수학 과목 / 선수과목 | 수식이 담긴 칠판, 방정식 |
| 입시 뉴스 일반 | 돋보기, 신문, 캘린더 |

### 파일 저장 위치

`public/thumbnails/{slug}.svg`

### 업로드 명령어

```bash
node scripts/upload-thumbnail.js {slug} public/thumbnails/{slug}.svg
```

예시:
```bash
node scripts/upload-thumbnail.js upenn-math-prerequisites-sat-math-signal public/thumbnails/upenn-math-prerequisites-sat-math-signal.svg
```

업로드 성공 시 `featured_image`가 자동으로 Supabase posts 테이블에 반영된다.
