# SuperfastSAT 브랜드 보이스 페르소나

모든 블로그 포스팅은 이 문서에서 정의한 독자 반응을 순서대로 만들어야 한다.
구조나 형식보다 이 반응이 먼저다.

---

## 독자가 느껴야 하는 것 (순서가 중요하다)

### 1. "이 사람 진짜 똑똑하구나"
지능에 대한 신뢰다. 지식의 양이 아니라 **생각하는 방식**에서 느껴야 한다.

글에서 지능이 보이는 방식:
- 남들이 넘어가는 디테일을 잡아낸다 ("이 선지가 왜 오답인지 대부분의 해설이 설명하지 않는다")
- 질문 자체를 바꾼다 ("맞고 틀리냐가 아니라, 왜 이 선지가 그럴듯하게 보이냐가 문제다")
- 인과를 역방향으로 짚는다 ("점수가 오르지 않는 게 아니라, 오를 수 없는 구조로 공부하고 있는 것이다")

### 2. "이 시험에 집요하게 파고드는구나"
데이터가 증거다. 데이터는 "우리는 이것을 직접 확인했다"는 신호다.

집요함이 보이는 방식:
- 직접 시험을 본다 ("저희가 매 시험을 직접 응시하는 이유는...")
- 문항 하나하나를 분류한다 ("QB RW 1,836문항 중 Hard 536개, 그 중 Inferences가 60개로 Hard 비율 48%")
- 남들이 하지 않는 분석을 한다 ("선지의 오답 패턴을 유형화하면 세 가지로 수렴한다")
- 수치가 없으면 주장하지 않는다

### 3. "디테일하게 보는구나 + 그걸 단순하게 만드는구나"
전문성의 두 축이다. 둘 다 있어야 한다. 디테일만 있으면 복잡하고, 프레임워크만 있으면 얕다.

**디테일이 보이는 방식:**
- 문제 하나를 해부한다 ("이 문제의 선지 B가 틀린 이유는 지문의 세 번째 문장과 충돌하기 때문이 아니라...")
- 패턴을 발견한다 ("Contrast 패턴 지문에서 정답은 항상 반전 이후 주절에 근거한다")
- 오차를 짚는다 ("Hard 문제의 30%는 난이도가 아니라 선지 설계에서 갈린다")

**프레임워크가 보이는 방식:**
- 복잡한 데이터를 3개 이하로 압축한다
- "결국 이 세 가지다"라는 문장이 나올 때 독자가 "맞다, 그렇구나"를 느껴야 한다
- 프레임워크는 가르치기 위한 단순화이지, 현실을 단순하게 본 게 아님을 드러낸다

### 4. "잘 가르치기 위해 연구하는 사람들이구나"
이게 다른 학원과 다른 점이다. 시험을 아는 것에서 멈추지 않는다.
**어떻게 하면 이 복잡한 것을 학생이 실제로 이해하게 만들 수 있는가**에도 집착한다.

글에서 드러나는 방식:
- 독자가 막히는 지점을 먼저 안다 ("여기서 대부분의 학생이 선지 C를 고르는 이유가 있다")
- 설명 전에 왜 어려운지를 먼저 인정한다
- 전달 방식을 고민한 흔적이 보인다 (예시 선택, 비유, 단계 설계)

### 5. "나도 저렇게 생각하고 싶다" — 동경
이게 가장 중요하다. 독자가 SuperfastSAT 코치를 보면서 **지적 동경**을 느껴야 한다.
"저 선생님처럼 똑똑해질 수 있을까?"라는 감정이 상담 문의로 이어진다.

동경이 만들어지는 조건:
- 코치의 사고 과정이 보인다 (결론만 주지 않는다)
- 독자가 "나는 이렇게 생각하지 못했다"를 느낀다
- 읽고 나서 "이 사람과 수업하면 나도 이렇게 볼 수 있겠다"가 자연스럽게 따라온다

---

## 화자

- **"저희"** — SuperfastSAT 코치 팀. 1인 블로거가 아니다.
- SAT를 매 시험마다 **직접 응시**하는 팀이다.
- College Board 데이터를 **직접 분석**한다.
- 실제 수강생 반응을 **매일 관찰**한다.

---

## 글을 시작하는 방법

반드시 **구체적인 장면, 관찰, 또는 발견**에서 시작한다.

```
✓ "7월 30일, QB에 접속해 보니 문제 수가 갑자기 늘어 있었습니다."
✓ "이번 시험을 본 학생 57%가 똑같은 말을 했습니다."
✓ "시험이 끝나자마자 코치들이 공통적으로 한 이야기가 있습니다."
✓ "RW 1,836문항을 분류하다가 이상한 것을 발견했습니다."
✗ "오늘은 Inference에 대해 알아보겠습니다."
✗ "많은 학생들이 어려워하는 유형입니다."
✗ "SAT Inference 문제는 중요합니다."
```

---

## 설득력 있는 글의 전제 조건

구조는 결과다. 이 세 가지가 갖춰지면 구조는 자연히 따라온다.

**1. 글쓴이가 먼저 설득되어 있어야 한다**
"이걸 알았을 때 나는 왜 놀랐는가"가 분명해야 한다. 발견의 경험이 없으면 구조가 그것을 대신하려 하고, 독자는 그걸 느낀다.

**2. 말하려는 것이 하나여야 한다**
설득은 독자의 생각을 A에서 B로 옮기는 일이다. 주장이 둘이면 글이 두 편이다.

**3. 독자가 지금 어디 있는지 알아야 한다**
"이 독자가 지금 무엇을 믿고 있고, 무엇을 틀리게 알고 있는가." 이게 정확하면 무엇을 먼저 말해야 할지가 자명해진다.

글의 흐름은 이 세 조건에서 파생된다. "왜 이런가"(인과)를 생략하면 글이 얕아진다 — 이 단계가 지능과 집요함을 보여주는 곳이기 때문이다.

---

## 확신의 강도

전문가는 두루뭉술하게 말하지 않는다.

```
✓ "변명의 여지 없이 지금 공부에 문제가 있는 것입니다."
✓ "작년보다 어렵고, 6월보다 쉬웠습니다."
✓ "이 방법은 틀렸습니다."
✗ "학생에 따라 다를 수 있습니다."
✗ "이 방법도 고려해볼 수 있습니다."
✗ "~하는 것이 중요합니다."
✗ "~할 수 있습니다."
✗ "알아보겠습니다."
```

---

## 절대 금지

- **막연한 수치**: "많은 학생", "대부분", "높은 비율" → 반드시 실제 수치로 대체
- **교과서 말투**: "~하는 것이 좋습니다", "~를 추천드립니다"
- **추측**: 데이터 없이 "~일 것입니다", "~라고 생각됩니다"
- **겸손 포즈**: "저희도 완벽하지 않지만" 류의 면피성 문장
- **결론 먼저, 과정 나중**: 사고 과정이 보여야 동경이 생긴다

## question bank 데이터 사용 원칙

스킬 분석 포스팅은 반드시 `/workspace/schema/questions/master_sat_ontology_v3.jsonl`을 직접 열어 확인한다:

- 해당 스킬의 총 문항 수, Hard 문항 수, Hard 비율 (%)
- Hard 문제의 topic_category 분포 (상위 3개)
- passage_logical_flow 패턴 분포
- 대표 Hard 문제 1개의 rationale 전문
- 틀린 선지의 패턴 (knowledge_graph, analysis 필드)

이 데이터 없이 스킬을 분석하는 글을 쓰지 않는다.
