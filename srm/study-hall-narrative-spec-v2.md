# 스터디홀 내러티브 작성 기준 — v2

학부모가 숫자를 직접 해석하지 않아도 오늘 자녀가 어떤 상태인지 파악할 수 있게 하는 것이 목표.

---

## 입력 데이터

| 항목 | 설명 |
|------|------|
| `durationMinutes` | 스터디홀 총 접속 시간 (분) |
| `totalProblems` | 푼 문항 수 |
| `correctCount` | 정답 수 |
| `accuracy` | 정답률 (0~100, 정수) |
| `skills[]` | 스킬별 정답/총문항 배열 |

---

## 전처리 규칙

### 볼륨 분류 (`volumeCtx`)

| 조건 | 값 |
|------|----|
| `totalProblems < 15` | 짧은 연습 세션 |
| `totalProblems < 40` | 보통 세션 |
| `totalProblems ≥ 40` | 집중 세션 |

### 성취 분류 (`perfCtx`)

| 조건 | 값 |
|------|----|
| `accuracy ≥ 85` | 우수한 성취 |
| `accuracy ≥ 70` | 안정적인 수준 |
| `accuracy ≥ 50` | 보완이 필요한 구간 |
| `accuracy < 50` | 기초 강화가 필요한 단계 |

### 스킬 정보

- **스킬명**: 영문 skill 명을 그대로 한다 (예: "Words in Context" → "Words in Context"유형)
- **skillLines**: skills를 total 내림차순 정렬 → 상위 4개 → `스킬명: 정답/총문항 (정답률%)` | 구분
- **weakestSkill**: skills가 2개 이상일 때만 사용. 정답률 오름차순 정렬, 동점이면 total이 많은 쪽 선택

### 문장 수 결정

| 조건 | 문장 수 |
|------|---------|
| `totalProblems < 15` 또는 `skills 없음` | 2문장 |
| 그 외 | 3문장 |

---

## 내러티브 작성 원칙

1. 숫자를 나열하지 않고, 그 숫자가 의미하는 **학습 상태를 해석**한다
2. 정답률에 따른 톤:
   - ≥85% → 강점·성취 강조
   - 70~84% → 잘한 점과 보완점 균형
   - 50~69% → 개선 방향 구체적 제시
   - <50% → 흔들리는 유형을 지목하되 **격려 톤 유지**
3. 취약 스킬이 있으면 반드시 그 **스킬 이름**을 문장에 포함
4. 문제 볼륨(짧은 연습 / 보통 / 집중 세션)이 드러나도록 서술
5. 마지막 문장은 **다음 수업에서의 구체적 보완 액션**으로 마무리

## User Content 예시

### 짧은 세션 (4문장)

```
학습 시간: 24분 / 짧은 연습 세션 / 총 2문항 / 정답 2개 / 정답률 100% [우수한 성취]
스킬별 성취: 중심 내용: 2/2문항 (100%)
```

### 일반 세션 (4문장)

```
학습 시간: 47분 / 집중 세션 / 총 52문항 / 정답 38개 / 정답률 73% [안정적인 수준]
스킬별 성취: 문맥 속 어휘: 14/18문항 (78%) | 근거 활용: 10/14문항 (71%) | 중심 내용: 8/11문항 (73%) | 연결어: 6/9문항 (67%)
가장 취약한 스킬: 연결어 (6/9문항)
```

## 엣지 케이스

| 케이스 | 처리 방법 |
|--------|-----------|
| `totalProblems === 0` | AI 호출 없이 `"${분}분간 스터디홀에 접속했습니다."` 고정 출력 |
| skills 없음 | skillLines 생략, weakestSkill 없이 2문장 생성 |
| skills 1개만 | weakestSkill 언급 생략 |
| 하루 세션 여러 개 | 날짜별 합산 (시간·문항·정답·스킬 누적) |
