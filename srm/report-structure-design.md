# 학부모 포털 리포트 구조 설계

> 기반 문서: `superfastsat-coaching-philosophy.md`
> 대상: 학부모 포털 — 학부모에게 전달되는 내러티브

---

## 설계 원칙

리포트는 활동별로 트리거되지만, 그 활동 데이터만 해석하지 않는다.
코칭 철학의 사이클(연습 → 검증 → 격차 분석 → 방향 결정)에서
오늘 활동이 어디에 위치하는지를 다른 시스템 데이터와 교차 참조해 설명한다.

리포트는 세 가지 질문에 답한다.

1. **오늘 어떤 상태인가** — 활동 데이터의 해석 (숫자가 아닌 학습 상태)
2. **이게 무엇을 의미하는가** — 다른 데이터와 교차했을 때 드러나는 패턴
3. **다음 수업에서 무엇을 할 것인가** — 코치 피드백에 근거한 방향

---

## 리포트 트리거와 입력 데이터

### A. 스터디홀 리포트

**트리거**: 스터디홀 세션 종료

**1차 데이터 (오늘)**

| 항목 | 설명 |
|------|------|
| 학습 시간 | 총 접속 시간 |
| 스킬별 정답률 | 어떤 스킬을 얼마나 잘 풀었는가 |
| 총 문항 / 정답 수 | 볼륨과 성취 |

**교차 참조 데이터**

| 출처 | 항목 | 교차 목적 |
|------|------|----------|
| 테스트센터 (최근 결과) | 동일 스킬의 검증 정답률 | 연습-검증 격차 확인 |
| 코치 레슨 피드백 (최근) | 코치가 지목한 취약 스킬/방향 | 오늘 연습이 코치 방향과 일치하는가 |

**리포트가 답해야 할 것**
- 오늘 연습한 스킬에서 반복되는 오류 유형이 있는가
- 같은 스킬의 테스트센터 성적과 격차가 있는가 (연습은 되는데 검증에서 무너지는가)
- 코치가 집중하라고 했던 스킬을 오늘 연습했는가

---

### B. 테스트센터 리포트

**트리거**: 테스트센터 세션 종료

**1차 데이터 (오늘)**

| 항목 | 설명 |
|------|------|
| 커리큘럼 제목 / 도메인 | 어떤 테스트를 봤는가 |
| 모듈별 정답률 | 흐름(상승/유지/하락) |
| 전체 정답률 | 오늘의 검증 성취 |

**교차 참조 데이터**

| 출처 | 항목 | 교차 목적 |
|------|------|----------|
| 스터디홀 (최근 결과) | 오늘 테스트에 나온 스킬의 연습 정답률 | 연습-검증 격차 확인 |
| 코치 레슨 피드백 (최근) | 코치가 예측하거나 주목한 취약점 | 오늘 결과가 코치의 진단을 확인하는가, 개선됐는가 |

**리포트가 답해야 할 것**
- 모듈 간 흐름에서 무너지는 지점이 어디인가
- 스터디홀에서 연습했던 스킬이 테스트에서 실제로 작동했는가
- 코치가 우려했던 부분이 오늘 테스트에서 드러났는가, 해소됐는가

---

### C. 단어 리포트

**트리거**: 단어 학습 세션 종료

**1차 데이터 (오늘)**

| 항목 | 설명 |
|------|------|
| 학습 단어 수 | 오늘 노출된 볼륨 |
| 정답률 / 마스터 수 | 오늘의 성취 |
| 복습 필요 단어 | 반복 오답 단어 |

**교차 참조 데이터**

| 출처 | 항목 | 교차 목적 |
|------|------|----------|
| 코치 레슨 피드백 (최근) | 코치가 지목한 단어 학습 방향 | 오늘 학습이 코치 방향과 일치하는가 |

**리포트가 답해야 할 것**
- 단어 학습이 암기 단계인가, 인지 오류 교정 단계인가 (코치 피드백 기반)
- 반복 오답 단어에 패턴이 있는가
- 코치가 집중하라고 했던 단어군을 오늘 다뤘는가

---

## 교차 참조 로직

### 연습-검증 격차 판정

스터디홀과 테스트센터의 **동일 스킬** 정답률을 비교한다.

| 격차 상태 | 해석 | 리포트 방향 |
|----------|------|-----------|
| 격차 없음 (±10%p 이내) | 연습한 것이 검증에서도 작동함 | 숙지 확인, 다음 스킬로 전환 신호 |
| 스터디홀 > 테스트센터 (10%p 이상) | 연습은 되나 압박 하에서 무너짐 | 연습량보다 적용 훈련이 필요한 단계 |
| 테스트센터 > 스터디홀 | 검증 환경에서 오히려 더 잘함 | 스터디홀 문제 수준이 낮을 가능성 |
| 스터디홀 데이터 없음 | 해당 스킬을 연습하지 않고 검증함 | 준비 없이 노출된 상태 |

### 코치 피드백 참조

가장 최근 코치 레슨 피드백을 읽고 두 가지를 확인한다.

1. **오늘 활동이 코치 방향과 일치하는가**
   — 코치가 "연결어 집중"이라고 했는데 오늘 연결어를 연습했는가
2. **오늘 데이터가 코치의 진단을 확인하는가, 개선을 보여주는가**
   — 코치가 우려했던 스킬이 오늘도 낮게 나왔는가, 올라왔는가

코치 피드백이 없으면 이 참조 항목은 생략한다.
코치 피드백이 있을 때만 "다음 수업 방향" 문장이 AI 추측이 아닌 근거 있는 계획이 된다.

## 내러티브 구조 (학부모용)

모든 리포트는 아래 3단 구조로 작성한다.

```
[1] 오늘 상태
    — 숫자가 아닌 학습 상태 해석
    — 어떤 스킬/단어에서 어떤 패턴이 보였는가

[2] 흐름 속 위치
    — 교차 참조에서 드러난 것
    — 연습-검증 격차 / 코치가 주목했던 지점과의 연결

[3] 다음 수업 방향
    — 코치 피드백이 있으면: 코치가 계획한 방향을 학부모 언어로 전달
    — 코치 피드백이 없으면: 오늘 데이터에서 도출되는 방향 제안
```

### 작성 원칙

- 숫자를 나열하지 않는다. 그 숫자가 의미하는 학습 상태를 해석한다
- 코치가 말할 법한 언어로 쓴다. 채점 결과 통보가 아니라 진단 설명이다
- 격려와 솔직함을 동시에 유지한다. 낮은 결과를 숨기지 않되 불안을 조장하지 않는다
- 마지막 문장은 항상 다음 수업에서 일어날 일이다. AI 추측이 아닌 데이터 기반 방향이어야 한다

## 미결 사항

| 항목 | 현재 상태 | 해결 방향 |
|------|----------|----------|
| 스킬 수준 교차 참조 | 스터디홀-테스트센터 간 스킬 매핑 로직 필요 | 동일 스킬명 기준 매칭 |
| 코치 피드백 접근 | 최근 N개 중 몇 개를 참조할지 미정 | 가장 최근 1개 우선, 없으면 생략 |
| 단어-RW 연계 | 단어 오류가 WIC 스킬에 영향하는지 연결 불명확 | 추후 설계 |
