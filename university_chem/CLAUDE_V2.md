## 0. v1 현재 상태 (2026-08-15 기준)

사용자가 확인한 구현 완료 기능:
- 이름 + 생년월일 + SAT 점수 입력

**⚠️ 문서-코드 불일치 주의**: 이 리포지토리의 `university_destiny_match.html`(마지막 동기화 시점 기준)에는 **이름 입력 필드와 친구 공유/비교 기능이 없습니다.** 위 목록은 사용자가 별도 세션(Claude Code 등)에서 추가 구현한 것으로 보입니다. v2 작업 시작 전 **실제 코드 상태를 먼저 확인**하고, 이 문서의 가정과 다르면 이 섹션부터 갱신하세요.

## 1. 사주 정밀도 개선 — 시(時)주 + 입학 예정 연도

### 문제
v1은 생년월일만 받아서 정통 사주 4주(년·월·일·시) 중 3주만, 그것도 일주는 `(day-1)%5`라는 임시 근사로 처리했습니다. "사주"를 표방하기엔 근거가 얕습니다.

### 1-1. 일주(日柱) 정확 계산 — 우선순위 최상
**이건 근사가 아니라 정확히 계산할 수 있습니다.** 일주는 절기와 무관하게 60갑자가 하루 단위로 균일하게 순환하므로, 기준일 하나만 있으면 율리우스 적일수(JDN)로 정확히 구합니다.

```
JDN 계산 → (JDN + offset) % 60 → 60갑자 인덱스
→ 천간 = index % 10, 지지 = index % 12
```
- 검증용 기준: 널리 쓰이는 기준점은 1900-01-01 = 갑술일(甲戌). **구현 후 반드시 복수의 만세력 사이트와 3개 이상 날짜로 교차 검증**할 것. offset을 한 번 잘못 잡으면 전체 결과가 조용히 틀어집니다.
- 일간(日干)은 사주에서 **본인 자신을 상징하는 가장 중요한 글자**입니다. 이게 정확해지면 v2의 다른 모든 해석(십신, 궁합)의 신뢰도가 올라갑니다.

### 1-2. 월주(月柱) — 절기 기반으로 승격
v1은 "3-4월=목" 식의 계절 근사였습니다. 정통 사주는 **입춘·경칩·청명… 12절기**를 월 경계로 씁니다.
- 절기는 매년 날짜가 1~2일 유동적입니다. 정밀 천문 계산 대신 **절기 근사 테이블**(연도별 ±1일 오차 허용)로 충분합니다. 근사임을 코드 주석에 명시하세요.
- **중요**: 입춘(2/4 전후) 이전 출생자는 사주상 **전년도 생**으로 칩니다. v1은 이 처리가 없어서 1~2월 초 생일자의 년주가 틀립니다. **v2에서 반드시 수정.**
- 월간(月干)은 년간에서 파생됩니다(월두법/五虎遁).

### 1-3. 시주(時柱) — 신규 입력
- 시지(時支): 2시간 단위 12지. 자시는 23:00–01:00로 날짜를 걸칩니다(야자시/조자시 논쟁 있음 — **단순하게 23:00부터 다음 날 자시로 처리**하고 주석에 선택 근거 남길 것).
- 시간(時干): 일간에서 파생(시두법/五鼠遁).
- **UX 핵심**: 태어난 시간은 모르는 사람이 많습니다. 필수로 만들면 이탈합니다.
  - "시간 모름" 옵션을 **기본값으로** 제공
  - 모름 선택 시 → 3주(년월일)만으로 계산하고, 결과에 "시주를 넣으면 더 정확해져요" 안내 → **재입력 유도 = 재방문 훅**
  - 시간을 넣은 경우 결과 카드에 "4주 완성" 뱃지 → 완성도에 대한 보상감

### 1-4. 입학 예정 연도 → 세운(歲運)
사용자가 입학할 연도(예: 2028년)를 받아서, **그 해의 간지와 사용자 사주의 상호작용**을 해석합니다.
- 2028년 = 무신년(戊申年). 연도→간지는 기존 `getYearStem/Branch` 재사용.
- 해석 축: 그 해 간지가 사용자 일간 기준 어떤 십신인가, 사용자 사주와 합/충 관계인가.
- 카피 예시: *"2028년(무신년)은 당신의 일간 기준 편재運 — 넓게 뻗어나가는 해예요. 이 해에 문을 두드리기 좋은 곳은…"*
- **이게 v2의 숨은 무기**: 입학 연도별로 결과가 달라지면, 같은 사람이 여러 번 돌려볼 이유가 생기고 "재수하면 어디 나와?" 같은 놀이가 가능해집니다.

### 1-5. 십신(十神) 도입 — 해석 깊이의 핵심
일간을 기준으로 다른 글자들과의 관계를 10가지로 분류하는 체계입니다. **오행 5개보다 훨씬 캐릭터가 선명**합니다.
- 비견/겁재(경쟁·동료), 식신/상관(표현·창의), 편재/정재(현실·수완), 편관/정관(규율·명예), 편인/정인(학문·수용)
- **정인(正印)이 강하면 학문운** — 대학 매칭 서비스와 서사가 정확히 맞아떨어집니다. 이 연결고리를 카피에 적극 활용하세요.
- 결과 카드에 "당신의 주도 십신: 정인 — 배움으로 성장하는 유형" 식으로 노출.

## 2. "왜 이 대학인가"의 근거 강화 — 대학에도 사주를 부여

### 핵심 발상
v1은 대학의 캐릭터 태그를 임의로 오행에 매핑했습니다(논리력=금 등). 자의적이고, 사용자가 "왜?"라고 물으면 답할 게 없습니다.

**v2에서는 대학 설립일 = 대학의 생년월일로 보고, 대학의 사주를 실제로 계산합니다.** 그러면 "사람 사주 vs 대학 사주" 궁합이라는 **정통 궁합법(합혼)** 이 그대로 성립합니다. 이게 그럴싸함의 근본 해결책입니다.

### 2-1. 대학 설립일 데이터 수집 — ⚠️ 가장 큰 난관
**정직하게 짚고 갑니다. 이건 생각보다 어렵고, 일부는 불가능합니다.**

| 유형 | 예시 | 대응 |
|---|---|---|
| 정확한 설립일 존재 | UC Berkeley(1868-03-23 Charter Day), 서울대(1946-10-15) | 그대로 4주 계산 |
| 연도만 알려짐 | 다수 | 아래 폴백 규칙 |
| 설립일 자체가 없음 | **옥스퍼드** (1096년경부터 강의 기록만, 설립 시점 불명) | 아래 폴백 규칙 |
| 설립일이 논쟁적 | UPenn(1740 vs 1755 — 실제로 학교가 순위 경쟁 때문에 바꾼 이력 있음) | 공식 발표 기준 채택 + 주석 |

**폴백 규칙 (설계 필수)**
- 월·일이 없으면 → **년주만 사용**하고, 결과 화면에 "설립 연도 기준" 이라고 **명시**. 없는 날짜를 지어내지 마세요. 이 서비스는 재미용이지만, 지어낸 사실을 사실처럼 표시하면 다릅니다.
- 옥스퍼드처럼 연도조차 불확실하면 → 대학 사주 궁합 대신 **위치 오행 + QS 지표 기반 매칭**으로 우회하고, "설립 시기가 전해지지 않는 학교라 다른 방식으로 봤어요"라고 안내. 오히려 이 문구 자체가 옥스퍼드의 유서 깊음을 강조하는 매력 포인트가 됩니다.

**수집 방법**: 각 대학 공식 홈페이지의 About/History 페이지가 1차 출처. 위키피디아는 교차검증용. 28개교(Tier 1)부터 하고, Tier 2 확장은 나중에.
**데이터 파일**: `data/university_saju.json` — `{ name, foundedYear, foundedMonth|null, foundedDay|null, dateConfidence: "exact"|"year_only"|"unknown", source }`

### 2-2. 대학 위치 → 방위 오행
설립일과 별개로, **위치는 모든 대학에 100% 존재하는 데이터**입니다. 폴백으로도 좋고 단독으로도 그럴싸합니다.
- 전통 오행 방위: **동=목, 남=화, 중앙=토, 서=금, 북=수**
- 적용안 A (지구 기준): 경도/위도로 대륙 내 상대 방위 산출
- 적용안 B (사용자 기준, **더 추천**): 한국(서울)에서 본 방위 — 미국 서부는 동쪽(태평양 건너), 유럽은 서쪽… 사용자 입장에서 "내가 어느 방향으로 나아가는가"라는 서사가 생깁니다. 유학이라는 맥락과 잘 맞습니다.
- 카피 예시: *"당신에게 부족한 수(水) 기운은 북쪽에서 옵니다. 캐나다 토론토대가 그 방향이에요."*
- **이미 QS 데이터에 `country`, `region`이 있습니다.** 위경도만 추가하면 됩니다.

### 2-3. 궁합 계산법 업그레이드 — 코사인 유사도 → 전통 합충 이론
v1의 코사인 유사도는 "비슷하면 잘 맞는다"는 논리인데, **사주에서는 부족한 걸 채워주는 관계가 더 좋은 궁합**입니다. 이게 훨씬 그럴싸하고, 설명하기도 좋습니다.

적용할 전통 개념:
- **용신(用神) 보완**: 사용자에게 약한 오행을 대학이 채워주면 고득점. *"당신은 화(火) 기운이 부족한데, 이 대학은 화 기운이 강해요"* — v1에서 이미 약한 오행을 계산하고 있으니 연결만 하면 됩니다.
- **삼합(三合)**: 신자진(수국), 해묘미(목국), 인오술(화국), 사유축(금국) — 사용자 지지와 대학 지지가 삼합이면 **최고 궁합**. "천생연분" 카피 근거.
- **육합(六合)**: 자축·인해·묘술·진유·사신·오미 — 삼합 다음 등급.
- **충(沖)**: 자오·묘유·인신·사해·진술·축미 — 충돌 관계. **이걸 "나쁨"으로 쓰지 말고 "긴장감 있는 자극형 궁합"으로 재해석**하세요. 재미용 서비스에서 나쁜 결과는 공유되지 않습니다.
- **상생상극**: 목생화·화생토·토생금·금생수·수생목 / 목극토·토극수·수극화·화극금·금극목

**점수 설계 원칙**: 최종 궁합 %는 여전히 78~99% 구간 유지(항상 긍정적). 단, 이제 그 숫자 뒤에 **"삼합이라서 97%"** 같은 진짜 이유가 붙습니다.

### 2-4. 결과 화면에 "궁합 근거" 섹션 신설 — **이게 2번의 진짜 목표**
지금은 결과가 "그냥 나온" 느낌입니다. 근거를 3줄로 보여주세요:

```
왜 이 대학인가?
  ① 설립 1868년 무진(戊辰)년 — 토(土)의 안정된 기운
  ② 당신의 일지 자(子)와 대학의 진(辰)은 삼합(申子辰) 수국 관계
  ③ 서울에서 동쪽 — 당신에게 부족한 목(木) 기운의 방향
```

이 세 줄이 **스크린샷 찍어 인스타에 올리고 싶게 만드는 핵심**입니다. 4번(바이럴)의 성패가 여기 달려 있습니다. 문장은 짧고 단정적으로, 물음표 없이.

## 3. 친구 비교 화면 — 픽셀 아트 캠퍼스

### 심리 설계
사용자 표현 그대로: *"난 이 대학 다닌다고 나왔는데, 넌 어디 다닌다고 나와?"*
→ 핵심은 **비교와 수집**입니다. 혼자 보는 결과가 아니라 여럿이 모인 화면이 있어야 합니다.

### 3-1. 화면 컨셉
- **픽셀 아트 캠퍼스 맵**: 대학 로고(기존 픽셀 방패 배지 재사용) 아래에 **친구 캐릭터가 떠 있는** 구조
- 같은 대학이 나온 친구들은 **같은 배지 아래 모임** → "우리 셋 다 예일이야!" 같은 반응 유도
- 캐릭터는 이름 이니셜/닉네임 + 픽셀 아바타. **아바타도 기존 배지와 동일한 해시 방식으로 자동 생성**(이름 해시 → 픽셀 캐릭터) — 수작업 없이 전원 고유 캐릭터 확보
- 캐릭터 위에 우세 오행 색상 오라를 얹으면 사주 서사와 연결됨 (목=초록, 화=빨강, 토=노랑, 금=흰색/금색, 수=검정/파랑 — 전통 오행 색 그대로)

### 3-2. 기술 설계 — ⚠️ v1과 다른 차원의 작업
지금까지는 **백엔드 없는 정적 페이지**였습니다. 친구 비교는 **여러 사용자의 결과를 한 화면에 모아야 하므로 상태 공유가 필수**입니다.

선택지:

| 방식 | 장점 | 단점 |
|---|---|---|
| **URL 인코딩** (결과를 쿼리스트링에 압축) | 백엔드 0, 즉시 구현 | 친구가 링크를 열어야만 보임, 누적 불가 |
| **Supabase** (기존 CRM에서 이미 사용 중) | 누적/그룹 가능, 익숙한 스택 | 개인정보 저장 → 아래 주의사항 |
| 아티팩트 `window.storage` | 프로토타입 즉시 가능 | 실배포 환경 아님 |

**추천 경로**: 1단계는 URL 인코딩으로 "1:1 비교"만 빠르게 출시 → 반응 보고 2단계에서 Supabase로 "그룹 캠퍼스" 확장. 처음부터 백엔드 만들면 출시가 늦어지고, 이런 콘텐츠는 타이밍이 생명입니다.

**⚠️ 개인정보 주의 (반드시 지킬 것)**
- 이 서비스는 **미성년자(SAT 준비생)가 주 사용자**입니다.
- 수집되는 건 이름 + 생년월일 + 태어난 시간 + SAT 점수 — **결합하면 상당히 민감한 조합**입니다. 특히 SAT 점수는 학업 정보이고, 생년월일+시간은 재식별 위험이 있습니다.
- 원칙:
  - 친구 공유 화면에는 **닉네임과 대학 결과만** 노출. 생년월일·시간·SAT는 **절대 공유 데이터에 포함하지 말 것**
  - 서버 저장 시 실명 대신 닉네임 권장
  - 저장한다면 만 14세 미만 처리(개인정보보호법상 법정대리인 동의) 검토 필요 → **법무 확인 후 진행**
  - 데이터 보관 기간 정하고 자동 삭제
- 이건 재미 프로젝트지만 개인정보는 재미의 영역이 아닙니다. Supabase 도입 시 이 항목 먼저 정리하세요.

## 4. 바이럴 설계 — 두 개의 진입점

> **⚠️ 원문 확인 필요**: 사용자 메시지의 4번 항목이 문장 중간에 잘렸습니다 (*"이 화면에도 역시나 픽셀아트금까지 작업된 결과를 말해줄게"*). 아래는 앞 문맥으로 추정한 내용이며, **작업 착수 전 사용자에게 4번 의도를 재확인**하세요.

### 추정한 요구사항
바이럴이 터져야 하는 지점이 **두 곳**이고, 둘 다 픽셀 아트 스타일이어야 함:

**① 친구가 링크를 타고 들어와 보는 첫 화면** (신규 유입 지점)
- 친구 결과를 보러 왔다가 → 자기도 해보고 싶어지는 구조
- 필수 요소: 초대한 사람의 결과가 픽셀 캠퍼스로 먼저 보이고, 그 아래 **"나도 해보기" CTA**
- 이 화면은 **로딩이 빨라야** 합니다. 650KB JSON 로드를 기다리게 하면 이탈합니다. → 첫 화면은 초대자 결과만 정적으로 보여주고, 전체 데이터는 CTA 누른 뒤 로드(지연 로딩)

**② 사주 입력 후 "나는 이 대학과 맞는다" 결과 화면** (공유 발생 지점)
- 인스타그램에 올리고 싶어지는 화면
- 필수: **PNG 이미지 저장** — 지금은 텍스트 복사만 됩니다. 인스타는 이미지 플랫폼이라 이게 없으면 바이럴이 안 됩니다. **v2 최우선 구현 항목.**
- 인스타 스토리 규격 **1080×1920 세로형** 별도 렌더링 (현재 카드 비율로는 스토리에 안 맞음)
- 이미지에 포함: 픽셀 배지 + 대학명 + 궁합% + **2-4의 "궁합 근거 3줄"** + 서비스명/URL 워터마크
- 구현: `html2canvas` 또는 canvas 직접 렌더링. 폰트 로딩 타이밍 이슈 주의(웹폰트가 안 실린 상태로 캡처되는 흔한 버그).

### 픽셀 아트 스타일 확장
기존 픽셀 방패 배지의 시각 언어를 두 화면 전체로 확장:
- 픽셀 폰트 도입 검토 (한글 픽셀 폰트는 선택지가 적음 — **갈무리체, 둥근모꼴** 등 확인 필요. 라이선스 확인 필수)
- 단, **가독성이 우선**입니다. 본문까지 픽셀 폰트로 하면 읽기 힘들어집니다. 제목/숫자만 픽셀 폰트, 본문은 Pretendard 유지 권장.
- 배경에 픽셀 캠퍼스 요소(건물 실루엣, 나무, 구름) 추가 — 알고리즘 생성 대신 **공통 배경 몇 종**을 만들어 대학 지역(북미/유럽/아시아)별로 배정하면 작업량이 감당됩니다.

## 5. 작업 순서 제안

바이럴 임팩트 대비 작업량 기준입니다.

**1순위 (바이럴 직결, 비교적 빠름)**
1. 결과 화면 **PNG 저장** (인스타 스토리 1080×1920) — 이거 없이는 나머지가 다 무의미
2. 궁합 근거 3줄 섹션 (2-4) — 대학 사주 없이 **위치 오행 + 기존 오행만으로도 먼저 구현 가능**

**2순위 (그럴싸함의 근본 해결)**
3. 일주 정확 계산 + 입춘 경계 수정 (1-1, 1-2)
4. 대학 설립일 데이터 수집 28개교 (2-1)
5. 합충 기반 궁합 계산 (2-3)

**3순위 (재방문·확산)**
6. 시주 입력 + 입학 연도 세운 (1-3, 1-4)
7. 십신 해석 (1-5)
8. 친구 비교 — URL 인코딩 방식 1:1부터 (3-2)

**4순위 (확장)**
9. Supabase 그룹 캠퍼스 + 개인정보 처리 정비
10. 픽셀 아트 스타일 전면 확장

## 6. v2에서 지킬 원칙

- **지어내지 않기**: 설립일이 없으면 없다고 표시. 사주 계산이 근사면 근사라고 주석. 재미용이라고 사실을 만들어내면 안 됩니다.
- **나쁜 결과 만들지 않기**: 충(沖)도 "자극형 궁합"으로. 낮은 점수도 78% 하한 유지. 공유되지 않는 결과는 실패입니다.
- **미성년자 데이터 보수적으로**: 공유 화면엔 닉네임과 대학만.
- **입시 서비스와 선 긋기**: SuperfastSAT 본 서비스는 "검증 가능한 주장만 한다"는 진정성 원칙 위에 있습니다. 이 사주 콘텐츠가 그 신뢰를 훼손하지 않도록, **재미용 콘텐츠임을 명확히 표시**하고 실제 입시 상담·합격 예측과는 확실히 분리하세요. 브랜드 계정에 올릴지 별도 계정으로 뺄지는 이 관점에서 재검토가 필요합니다.
