### C-3. 실명이 URL에 평문으로 노출됨

WORK_SUMMARY 5의 테스트 URL:
```
#g=지수:0:91,민준:4:87
```

그리고 3-4에서 입력 필드가 **"닉네임" → "이름"으로 변경**됨. 즉 **실명이 URL 해시에 들어가 카카오톡으로 유통**됩니다.

- 이 URL은 카톡 대화방, 링크 미리보기 서버, 브라우저 히스토리, (호스팅 설정에 따라) 서버 액세스 로그에 남음
- 대상이 **미성년자**이고, 함께 수집하는 값이 **이름 + 생년월일 + 태어난 시간** — 재식별 가능성이 있는 조합
- 이전 세션에서 정한 원칙("공유 데이터에는 닉네임과 대학 결과만")과 **정면으로 어긋남**

**조치 (택1 이상)**
- 공유 URL에는 **닉네임/이니셜만** 사용 (입력은 이름으로 받되 공유 시 변환)
- 또는 이름 필드 옆에 *"친구에게 보이는 이름이에요"* 를 명시하고 별명 입력을 권장
- 생년월일·태어난 시간은 **어떤 경우에도 URL에 넣지 말 것** (현재 안 들어가는 것으로 보이나 확인 필요)

## 🟠 목표 미구현 — 인스타 팔로워 전환

서비스 목표는 **`@superfastsat.official` 팔로워 증가**로 확정됐으나, 현재 구현은 **앱 사용자만 늘리고 팔로워는 늘리지 않는 구조**입니다. 관련 기능이 전부 없음.

### O-1. OG 이미지 없음
카톡으로 링크를 보내면 사람들이 실제로 보는 건 **미리보기 카드**. 여기가 비어 있으면 "친구가 링크를 열게 만드는" 단계가 끊김.
- 동적 OG는 서버리스 필요(`@vercel/og`) → **배포 환경 결정(현재 미정)과 직결**
- 1단계 대안: 학교별 정적 OG 이미지를 미리 생성해두고 참조

### O-2. @핸들·태그 보상 없음
`exportStoryImage()`가 카드 PNG를 저장하지만, 이미지에 **계정 핸들이 없으면 팔로워로 이어지지 않음**.
- 이미지에 **@superfastsat.official 크게** 삽입 (이미지 속 URL은 클릭 불가라 무의미)
- 태그 보상 문구 삽입: *"@태그하면 스토리에 올려드려요"* → 리포스트 루프
- 리포스트는 사람이 하는 운영 작업 — 하루 처리량 기준을 미리 정할 것

### O-3. 스토리 규격 아님
현재 "결과 카드 PNG 저장" = 카드 비율. 인스타 스토리는 **1080×1920 세로**. 그대로 올리면 위아래가 비거나 잘림.
- 화면 카드와 **별도의 스토리용 렌더링 레이아웃**이 필요

### O-4. 링크인바이오 / 댓글→DM 동선 없음
앱을 프로필 링크에 두고, 게시물에서 *"댓글에 '대학' 남기면 DM"* 으로 유도하는 진입 설계가 없음. 팔로워 전환의 핵심 경로.

## 🟡 검증 필요 (코드 확인 후 판단)

### V-1. 분포 개선에 측정치가 없음
"103개교 중 52개교가 매칭되지 않던 문제 해소"라고 적혀 있으나 **수치가 없음**. 합의된 목표는:
- **최다 학교 비중 10% 이하**
- **등장 학교 수 전체의 80% 이상**

생일 전수(예: 2006~2010년생 1,826일) 시뮬레이션으로 측정하고 결과를 기록할 것. 개선 전 기준선은 하버드 29.2% / 옥스퍼드 19.8% / 등장 17개교였음.

### V-2. `computeMatch(birthdate, satScore, hourBranch)` — satScore 잔존
SAT는 폼에서 제거됐는데 **함수 시그니처에 파라미터가 남아 있음**. 내부에 필터링 로직이 남아 있으면 조용히 후보를 줄일 수 있음. 완전 제거 확인 필요.

### V-3. 사주 계산 정확도 — 이전 지적 사항 반영 여부 불명
WORK_SUMMARY에 언급이 없어 확인 필요:
- **입춘 경계 처리** — 입춘(2/4경) 이전 출생자는 사주상 **전년도 생**. 미처리 시 1~2월 초 생일자의 **년주가 틀림**. 로딩 화면에 "癸未年生"을 띄우는 만큼 틀리면 바로 드러남
- **일주(日柱)** — 여전히 `(day-1)%5` 근사인지? 율리우스 적일수로 **정확히 계산 가능**한 값임
- **시주(時柱)** — 12지 select만 받는 것으로 보임. 시주는 **시지 + 시간(천간)** 이며 시간은 일간에서 시두법으로 파생됨. 시지만 쓰면 시주의 절반만 반영
- **음력 변환 후 처리** — solarlunar로 양력 변환하는 건 맞음. 다만 사주의 월 경계는 음력 초하루가 아니라 **절기**이므로, 변환 후 절기 기준으로 월주를 잡는지 확인

### V-4. html2canvas 렌더링 리스크
알려진 실패 케이스가 두 개 겹쳐 있음:
- **웹폰트** — 폰트 로딩 완료 전 캡처하면 기본 폰트로 찍힘. `document.fonts.ready` 대기 필요
- **SVG `clipPath`** — 픽셀 방패 배지가 clipPath를 사용. html2canvas에서 clipPath 미지원/오작동 사례 많음 → **배지가 통째로 안 나올 수 있음**
- 실기기(iOS Safari 특히)에서 반드시 확인. 실패 시 대안은 canvas 직접 렌더링

### V-5. `#g=` 그룹 상태의 한계
URL 해시에 멤버를 누적하는 방식은 백엔드 없이 빠르게 검증하기 좋은 선택이나:
- 멤버가 늘수록 **URL이 길어져** 카톡에서 잘리거나 공유가 불편해짐 (상한 정해둘 것)
- 링크를 받은 사람이 **자기를 추가한 새 URL을 다시 뿌려야** 그룹이 자람 → 중간에 한 명이 안 하면 체인이 끊김
- 한글 이름이 URL 인코딩되며 길이가 3배(`%EC%A7%80%EC%88%98`) → 길이 문제 가중

## 🟢 콘텐츠·기능 공백

### G-1. 설명 문장이 대부분 비어 있음
`description_templates.json` 미완성 → **Tier2 75개교(전체의 73%)에 설명 없음**. 결과의 대다수가 빈약한 카드로 나옴. 공유 동기에 직접 타격.

### G-2. "왜 이 대학인가" 근거 미구현 — 사용자 요구사항 2번 미해결
v2에서 정의한 핵심 개선이 들어가지 않음:
- **대학 설립일 → 대학의 사주** (사람 사주 vs 대학 사주 궁합)
- **대학 위치 → 방위 오행** (동=목, 남=화, 중앙=토, 서=금, 북=수)
- **궁합 근거 3줄 섹션** — 스크린샷을 찍고 싶게 만드는 핵심 요소

### G-3. `TRAIT_OVERRIDES`는 분포는 고쳤지만 근거는 못 고침
103개교에 5개 트레이트를 직접 지정하는 방식은 **결과 쏠림 해결에는 효과적**이나, 그 값 자체가 사람이 정한 자의적 배정이라 **"왜 이 대학인지"에 대한 답은 여전히 없음**. G-2의 설립일·위치 도입이 이 문제의 근본 해법이며, 분포에도 추가로 기여함.

### G-4. 네이밍 미정
`합격 통지서` / `ADMISSION FORTUNE` 계열 카피가 남아 있는지 확인 필요. 예측 톤을 걷어내기로 했고, 후보는 (a) 궁합·인연 유지 (b) **"전생에 다녔던 대학"**. 3번 픽셀 캠퍼스와 4번 바이럴 화면 카피가 여기에 종속되므로 **먼저 확정하는 게 효율적**.
